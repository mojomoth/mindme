- 03 목록도 맨 아래로 내리면 제목 '어떤 나와 이야기할까요?'가 `9:41`·아일랜드와 겹치고 마스코트 잎이 잘린다(`critic-visual-r1-desktop-s3-list-bottom.png`).
- 데스크톱에서는 이 스크롤을 피할 수 없다. 02는 처음 화면에서 '사진 업로드' 버튼이 생성 버튼에 가려 스크롤해야 누를 수 있다(`critic-visual-r1-desktop-s1-create-top.png`, 스크롤 범위 100px). 03은 페르소나가 3개만 돼도 하단 안내가 스크롤해야 보인다(`critic-visual-r1-scroll.json`).

- 고칠 방향(제안): 목업 상태바 영역(`--mm-safe-top` 높이)에 `var(--mm-bg)` 배경을 깔거나, 스크롤 영역이 안전 영역 아래에서 시작하게 한다. 모바일(<=600px)에는 가짜 상태바가 없어 해당하지 않는다.

## P2

1. **긴 이름일 때 페르소나 이름이 가운데에서 잘린다.** 이름이 20자이면 core `personaName`이 40자 제한에 맞추려고 사건 제목을 자른다. 그 결과 목록에 `체육대회 계주 때문에 친구와 다…의 남궁하늘빛초롱별…`처럼 말줄임이 두 번 들어가고, 프로필 시트 이름 칸에도 `…`가 그대로 저장된다(`critic-visual-r1-mobile-03-list.png`, `*-06-profile-sheet.png`). 카드 레이아웃은 깨지지 않는다(2줄 제한, 넘침 0건). 보통 길이(2~4자) 이름에서는 생기지 않는다.
2. **03 하단 안내('다른 순간의 나도 만나보세요')가 처음 화면에서 생성 버튼에 가린다.** 데스크톱은 페르소나 3개에서 보이지 않고, 모바일은 마스코트 머리만 버튼 뒤로 삐져나온다(`critic-visual-r1-mobile-03-list.png`). 스크롤하면 보인다. 구현자가 이미 기록한 P2와 같다.
3. **02 모바일: 이름·나이 줄이 추가되어 '내 얼굴 사진' 카드가 처음 화면에서 생성 버튼에 반쯤 가린다**(`critic-visual-r1-mobile-02-create.png`). 스크롤하면 보인다.
4. **여러 줄 입력란이 내부 스크롤 상태에서 위·아래 줄이 반쯤 보인다.** 04 상황 설명(3줄 높이), 프로필 시트의 말투·기억 칸이 그렇다(`*-04-modal.png`, `*-06-profile-sheet.png`). 두 모델이 모두 지적했다. 입력란 동작 자체는 정상이다.
5. **프로필 시트가 드래프트 시각 언어보다 일반 설정 폼에 가깝다.** 입력 칸 5개가 연달아 놓인 구성이라 Sonnet 6점, Codex 7점을 받았다. 색·모서리·버튼은 드래프트와 같다. 문구('쉼표로 나눠 적어요', '한 줄에 하나씩', '정말 지울까요?')는 자연스럽고 상투적인 표현은 없다.
6. **진행 화면은 흔한 스피너 체크리스트 형태다.** 어울림은 두 모델 모두 8점이다. 문구('1~2분쯤 걸려요. 화면을 켜 둔 채 기다려 주세요.', '앞으로의 나를 만나러 가는 중')는 맥락에 맞고 no-ai-slop 체크리스트에 걸리는 표현이 없다. 모달 진행 화면에서는 두 단계 스피너가 동시에 돌아 단계 구분이 약하다.
7. **hallmark 체크리스트의 '리터럴 색 금지'**: 새로 만든 `Working.module.css`(6곳)와 `ProfileSheet.module.css`(10곳)에 hex 리터럴이 있다. 기존 화면 CSS(Conversation 15, PersonaCreate 15 등)와 같은 관행이고 화면에 보이는 문제는 아니다. 둘 다 `:focus-visible`과 `prefers-reduced-motion`은 있다.
