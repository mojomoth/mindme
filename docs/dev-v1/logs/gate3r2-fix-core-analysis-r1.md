## 재현 (고치기 전)

`parseKakao` 를 Node 로 직접 돌렸다. AI 호출은 없다.

```
system: [["2019-03-01","23:50","잘 자\n2019년 3월 2일 토요일"],["2019-03-02","09:00","안녕"]]
eof:    [["2019-03-01","23:50","잘 자\n2019년 3월 2일 토요일"]]
pc:     [["2019-03-01","잘 자\n2019년 3월 2일 토요일"],["2019-03-03","안녕"]]
mid:    [["2019-03-01","21:00","기억나?\n2019년 3월 2일 토요일\n그날 비 왔잖아"],["2019-03-01","21:05","응"]]
```

- system: `['…오후 11:50, 이지우 : 잘 자', '2019년 3월 2일 토요일', '박서진님이 들어왔습니다.', '2019년 3월 2일 오전 9:00, 박서진 : 안녕']`. 구분선이 첫 메시지 본문에 붙었다.
- eof: 구분선이 파일 마지막 줄일 때도 마찬가지로 앞 메시지에 붙었다.
- pc: PC 판에서 날짜 모양 줄 바로 뒤에 다음 날짜 구분선(`--- 2019년 3월 3일 일요일 ---`)이 올 때도 같았다.
- mid: 원래 고친 경우(날짜 모양 줄 뒤에 일반 본문이 이어짐)는 본문에 남는다. 이 동작은 그대로 지켜야 한다.

원인은 `opensDay` 였다. 다음 비지 않은 줄이 같은 날짜의 `MOBILE_LINE` 일 때만 true 를 돌려줬기 때문에, 시간 없는 시스템 줄이나 파일 끝, PC 날짜 구분선 앞에서는 false 가 나왔다.

## 수정

`parse.ts` 의 `opensDay` 만 바꿨다. 다음 비지 않은 줄을 보고 이렇게 판단한다.

| 다음 줄 | 판단 |
|---|---|
| 없음(파일 끝) | 구분선 |
| 같은 날짜 `MOBILE_LINE` (시간 있는 시스템 줄 포함) | 구분선 (기존) |
| 다른 날짜 `MOBILE_LINE` | 본문 (기존) |
| `PC_DATE` | 구분선 |
| 시간 없는 `SYSTEM` | 구분선 |
| 그 밖의 줄 (일반 본문, `[이름] [오후 …]` PC 메시지, CSV 줄) | 본문 (기존) |

- `MOBILE_LINE` 을 `SYSTEM` 보다 먼저 검사한다. 시간 있는 시스템 줄(`2019년 3월 2일 오전 9:00, 박서진님이 들어왔습니다.`)은 `SYSTEM` 에도 걸리므로, 날짜가 다를 때 구분선으로 잘못 읽지 않게 하려는 순서다.
- PC 메시지 줄 앞에서는 지금처럼 본문으로 둔다. 구분선으로 읽으면 `day` 가 바뀌어 다음 PC 메시지 날짜가 틀어진다. 원래 analysis-1 이 고친 버그가 바로 이것이다.
- 다음 줄이 또 모바일 날짜 모양 줄(`MOBILE_DATE`)인 경우는 넣지 않았다. 재귀로 판단하면 날짜 줄만 수만 개인 입력에서 스택이 넘치거나 O(n²)이 된다. 실제 내보내기는 메시지 없는 날의 구분선을 쓰지 않으므로, 지금처럼 앞 줄은 본문으로 남는다(날짜는 바뀌지 않음).
- 감수한 점: PC 판 여러 줄 메시지가 날짜 모양 줄로 끝나고, 바로 뒤가 다음 날 구분선·시스템 줄·파일 끝이면 그 줄은 구분선으로 읽혀 본문에서 빠진다. 날짜는 틀어지지 않는다(다음 PC 구분선이 곧바로 `day` 를 다시 정한다). 과제가 요구한 대로 구분선 쪽을 택했다.

## 테스트

`analysis.test.ts` 에 `kakao: 날짜 구분선 뒤가 시간 없는 시스템 줄·PC 날짜 구분선·파일 끝이어도 구분선으로 읽는다` 를 더했다.

- 시스템 줄: `[['2019-03-01','잘 자'], ['2019-03-02','안녕']]`
- 파일 끝: `[['2019-03-01','잘 자']]`
- PC 다음 날짜 구분선: `[['2019-03-01','잘 자'], ['2019-03-03','안녕']]`

기존 테스트 `여러 줄 메시지 속 날짜 구분선 모양 줄은 본문으로 남고 다음 메시지 날짜를 바꾸지 않는다`(Android·PC)는 손대지 않았고, 그대로 통과한다.

고치기 전 `parse.ts` 를 /tmp 에 꺼내 같은 입력을 돌렸다. 세 경우 모두 구분선이 본문에 붙어 새 테스트가 실패한다. 고친 뒤에는 통과한다.
